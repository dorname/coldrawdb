# 变更提案：feat-room-diagram-picker

> module: core | created: 2026-10-31

## 变更原因
GitHub Issue #56：创建房间时原生下拉可能包含 350+ 图表，不能搜索或按最近修改排序；大量同名图缺少 ID、表/关系数和更新时间，无法区分空图与完整模型；删除按钮紧邻关联主操作，误触成本高；只想个人建模的用户也被迫先创建协作房间。

## 变更类型
设计级（S04 工作空间入口与图表摘要只读合同完善，含新增个人建模入口及 queryAll 响应的向后兼容增量字段）。

## 变更范围
- 影响的需求文档：无新增场景；沿用 S01 个人编辑与 S04 房间创建目标
- 影响的功能规格：`core-S04-room-lifecycle-design.md` §3 S04.1
- 影响的业务场景：S04（图表候选与创建房间），复用 S01 个人编辑器加载/保存通路
- 影响的场景时序：`core-S04-room-lifecycle.md` 新增图表候选与个人建模时序
- 影响的 API：既有 `GET /diagrams/queryAll` 响应增加 `table_count`、`reference_count`；不新增端点，既有字段保持不变
- 影响的 DB 表：只读查询 `diagram` / `table` / `reference`，无 Schema 变更
- 影响的编排测试：无（前端交互与后端单元/真实浏览器覆盖）
- 影响的测试：`core-S04-test-cases.md`，新增 UT-S04-21、UT-S04-UI-19、ST-S04-UI-18，修订 ST-S04-UI-16
- 影响的 smoke 测试：无

## 部署影响
- 是否需要部署：否
- 部署原因：前后端只读摘要与交互变更，由完整验收覆盖，无独立部署任务
- 影响环境：无
- 是否涉及数据迁移：否
- 是否需要回滚预案：否
- 是否需要 smoke：否

## 变更概述
将创建房间的原生下拉替换为可搜索图表选择器：按最近修改排序，支持名称和 ID 搜索，每项显示名称、短 ID、revision、表/关系数与更新时间；已绑定活跃房间的图继续排除。当前选中项始终有独立摘要，搜索无结果提供明确空态，不因过滤隐式改变选择。

同一选择器复用于「个人建模」入口：可新建命名空白图并选择引擎，或打开未绑定房间的已有图，加载完成后进入无 room 上下文的个人编辑器。危险删除移到独立图表管理区，二次确认展示名称、完整 ID 和规模信息，避免同名误删。后端 queryAll 通过单条只读 SQL 聚合计数，避免 350+ 图时逐图请求。
